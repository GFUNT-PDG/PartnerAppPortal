CrmSync — DAILY INCREMENTAL SYNC (watermark that actually persists)
================================================================================

WHY YOUR OLD FLOW WAS NOT INCREMENTAL
------------------------------------
You had:
  1) Initialize variable LastSyncTime = 1900-01-01   ← runs EVERY time
  2) Filter: modifiedon gt LastSyncTime
  3) At the end: Set variable = utcNow()

Step 3 does nothing for the next run, because Step 1 resets to 1900 again.
Result: every run re-pulls almost everything.

FIX: store LastSyncTime in SQL (dbo.CrmSyncWatermark), read it at start,
write it at end. That survives between runs.


PART A — RUN THIS SQL ONCE (Azure Query editor / SSMS)
------------------------------------------------------
File: C:\PartnerAppPortal\src\sql\CreateCrmSyncWatermark.sql

Creates:
  - dbo.CrmSyncWatermark table
  - dbo.GetCrmSyncWatermark
  - dbo.SetCrmSyncWatermark


PART B — FLOW STRUCTURE (daily incremental)
-------------------------------------------
Recurrence
  Frequency: Day
  Interval: 1
  Time: pick a quiet hour (example 2:00 AM)
  Time zone: your local zone

└── Execute stored procedure: GetCrmSyncWatermark
      WatermarkKey = CrmAccounts
      (save the LastSyncUtc output)

└── List rows (Accounts)
      Filter rows:
        modifiedon gt @{body('GetCrmSyncWatermark')?['resultsets']?['Table1']?[0]?['LastSyncUtc']}

      *** If that path looks different in your run output, open a test run,
          expand GetCrmSyncWatermark → outputs → copy the exact path to LastSyncUtc.
          Common alternates:
            @{first(body('GetCrmSyncWatermark')?['resultsets']?['Table1'])?['LastSyncUtc']}
            @{outputs('GetCrmSyncWatermark')?['body/resultsets/Table1/0/LastSyncUtc']}

└── Apply to each (value)
      └── Condition: primary contact present?
          ├── YES: Get Contact → UpsertCrmAccount → SetCrmAccountSalesAcceleratorAccess
          └── NO:  UpsertCrmAccount → SetCrmAccountSalesAcceleratorAccess

└── Execute stored procedure: SetCrmSyncWatermark
      WatermarkKey = CrmAccounts
      LastSyncUtc  = @{utcNow()}

IMPORTANT: SetCrmSyncWatermark must be AFTER Apply to each (same level as
List rows), NOT inside the loop. One watermark update per run.

PART D — FIRST RUN / BACKFILL
-----------------------------
First time after creating the watermark table, LastSyncUtc is 1900-01-01,
so the first run does a FULL sync (good).

After that succeeds, watermark becomes "now", and later daily runs only
get Accounts with modifiedon newer than that.

After adding Sales Accelerator Access to the flow, force one full sync so
accounts that already have Yes in CRM (but were not recently modified)
still get the SQL flag:

To force another full sync later:
  UPDATE dbo.CrmSyncWatermark
  SET LastSyncUtc = '1900-01-01T00:00:00'
  WHERE WatermarkKey = N'CrmAccounts';

OPTIONAL SAFER WATERMARK (advanced)
-----------------------------------
Instead of utcNow() at the end, save the MAX(modifiedon) from the batch
you just processed. That avoids missing records if the run started mid-second.
For ~100 accounts, utcNow() after a successful loop is fine.
