WHAT THIS FLOW DOES
-------------------
1. Runs on a DAILY schedule
2. Reads last sync time from SQL (persisted watermark)
3. Lists ONLY Accounts modified since that time
4. For each Account:
   - If Primary Contact exists → get that Contact's name + email
   - Upsert into SQL dbo.CrmAccounts
5. Saves new watermark so the next day is incremental
6. Partner portal login matches CrmAccounts.Email (exact or domain)
7. Copies CRM "Sales Accelerator Access" (Yes/No) into CrmAccounts.SalesAcceleratorAccess
   so only Yes partners see the Sales Accelerator tile / app

STEP 3 — GET WATERMARK (start of flow)
--------------------------------------
Add action: SQL Server → Execute stored procedure (V2)
  Rename to: GetCrmSyncWatermark
  Server: pacappsql01.database.windows.net
  Database: pacappdb01
  Procedure: [dbo].[GetCrmSyncWatermark]
  WatermarkKey: CrmAccounts

*** Do NOT use Initialize variable LastSyncTime = 1900.
    That resets every run and breaks incremental sync.


STEP 4 — LIST ROWS (ACCOUNTS)
-----------------------------
Add action: Microsoft Dataverse → List rows

Settings:
  Table name: Accounts

  Select columns:  (paste exactly, one line — adjust other cr3f8_* names only if
  your old flow used different ones)

    accountid,name,primarycontactid,emailaddress1,telephone1,modifiedon,cr3f8_accountexecutive,cr3f8_developmentdirector,cr3f8_customerexperiencecx,cr3f8_salesacceleratoraccess

  If that expression returns blank on first test, open the run output for
  GetCrmSyncWatermark and adjust the path to wherever LastSyncUtc appears.

STEP 7 — IF YES (has primary contact)
-------------------------------------
Inside YES branch:

A) Add action: Microsoft Dataverse → Get a row by ID
   Rename to: Get Primary Contact
   Table name: Contacts
   Row ID: Primary Contact (primarycontactid) from the Account in the loop
   Select columns:
     firstname,lastname,emailaddress1

B) Add action: SQL Server → Execute stored procedure (V2)
   Rename to: Upsert Account With Contact
   Server: pacappsql01.database.windows.net
   Database: pacappdb01
   Procedure: [dbo].[UpsertCrmAccount]

   Parameter mappings:
     AccountId            = Account (accountid) from List rows item
     Name                 = Account Name
     PrimaryContact       = use Expression (click fx):

       trim(concat(coalesce(outputs('Get_Primary_Contact')?['body/firstname'], ''), ' ', coalesce(outputs('Get_Primary_Contact')?['body/lastname'], '')))

     AccountExecutive     = same cr3f8 field as your old flow
     DevelopmentDirector  = same cr3f8 field as your old flow
     CustomerExperienceCx = same cr3f8 field as your old flow

     Email                = use Expression (click fx):

       coalesce(outputs('Get_Primary_Contact')?['body/emailaddress1'], items('Apply_to_each')?['emailaddress1'])

     Phone                = Main Phone / telephone1
     ModifiedOn           = Modified On
     SyncedOn             = use Expression: utcNow()

C) Add action: SQL Server → Execute stored procedure (V2)
   Rename to: Set Sales Accelerator Access (With Contact)
   Procedure: [dbo].[SetCrmAccountSalesAcceleratorAccess]
   Parameter mappings:
     AccountId                 = Account (accountid) from List rows item
     SalesAcceleratorAccess    = use Expression (click fx):

       string(items('Apply_to_each')?['cr3f8_salesacceleratoraccess'])

   That CRM field is a Yes/No two-option. Dataverse sends true/false (sometimes 1/0).
   The SQL proc treats Yes / true / 1 as granted; anything else is No.


STEP 8 — IF NO (no primary contact)
-----------------------------------
Inside NO branch:

Add action: SQL Server → Execute stored procedure (V2)
  Rename to: Upsert Account Only
  Same server / database / procedure

  Parameter mappings:
    AccountId            = accountid
    Name                 = Account Name
    PrimaryContact       = (leave empty)
    AccountExecutive     = same as above
    DevelopmentDirector  = same as above
    CustomerExperienceCx = same as above
    Email                = Account Email (emailaddress1)   ← account only
    Phone                = Main Phone
    ModifiedOn           = Modified On
    SyncedOn             = utcNow()

Then add the same SetCrmAccountSalesAcceleratorAccess action as in the YES
branch (rename it Set Sales Accelerator Access Only). Same AccountId and
same string(items(...)?['cr3f8_salesacceleratoraccess']) expression.


STEP 9 — SET WATERMARK (END OF FLOW — OUTSIDE THE LOOP)
-------------------------------------------------------
After Apply to each (same level as List rows, NOT inside the loop):

Add action: SQL Server → Execute stored procedure (V2)
  Rename to: SetCrmSyncWatermark
  Procedure: [dbo].[SetCrmSyncWatermark]
  WatermarkKey: CrmAccounts
  LastSyncUtc: @{utcNow()}

COMMON MISTAKES
---------------
- Putting Condition AFTER List rows (wrong) — must be INSIDE Apply to each
- Putting SetCrmSyncWatermark INSIDE Apply to each (wrong) — once per run only
- Mapping PrimaryContact to primarycontactid GUID (wrong) — use contact name
- Mapping Email only to Account emailaddress1 (wrong for partner login)
- Keeping Initialize variable = 1900 (destroys incremental sync)
- Action names in expressions must match exactly
  Get Primary Contact → Get_Primary_Contact in expressions
